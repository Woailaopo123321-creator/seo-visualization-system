当前架构（2026）

短期记忆线程范围内。通过 Checkpointer 持久化图状态。支持恢复、HITL、时间旅行。范围：单次对话。
长期记忆跨线程。通过 Store 存储结构化数据（用户偏好、事实）。命名空间隔离。节点可直接读写。
LangMem在 Store 之上提供记忆提取与管理。支持语义（事实）、情景（经历）、程序（指令）三类记忆。
旧类已弃用ConversationBufferMemory 等已移至 langchain-classic，计划在 2.0 移除。推荐使用 checkpointer + store。

经典记忆类型（参考）

Buffer完整保存所有消息。精确但 token 无限增长。适合短对话。
Window仅保留最近 k 轮。固定开销，丢失早期细节。
Summary用 LLM 压缩历史为摘要。节省 token，可能丢失细节。
SummaryBuffer近期原文 + 早期摘要。平衡精确与成本。
Entity抽取实体属性。适合跟踪人物/事物事实。
Vector向量检索相关历史。适合语义召回大量记录。

上下文管理策略

裁剪（Trim）调用模型前只保留最近消息。简单但可能丢失关键信息。
删除（Delete）从状态永久移除消息。适合清理无关内容。
摘要（Summarize）用模型压缩早期消息为摘要。保留语义，降低 token。
自定义中间件实现特定过滤逻辑（如按主题、按实体）。

与本系统关系

  • 当前系统使用进程内缓存与 ReAct 轨迹日志，无跨请求记忆。
  • 若需对话连续性，可评估引入 checkpointer 机制。
  • 长期知识（用户偏好、SEO 策略）可考虑 Store 或外部持久化。
  • 摘要策略可用于压缩工作流轨迹，避免日志膨胀。

2026 年 LangChain 记忆以 LangGraph 的 checkpointer（短期）与 store（长期）为核心。经典 Buffer/Summary 类已弃用，但思想仍可用于上下文管理。
