核心模式

API Gateway / 后端聚合

单一入口，负责路由、认证、限流与响应聚合。对应本系统的 Coordinator 调度层。

Database per Service

每个服务拥有自己的数据存储，避免共享数据库耦合。Agent 中间结果与任务状态应隔离。

Saga（分布式事务）

跨服务业务流程由本地事务序列 + 补偿操作组成。编排式（Orchestration）由中央协调器驱动；编舞式（Choreography）由事件驱动。

弹性模式

Circuit Breaker
失败阈值触发后快速失败，避免级联。状态：Closed → Open → Half-Open。
Retry + Backoff
对暂时性失败重试，带指数退避与抖动，防止重试风暴。
Bulkhead
隔离资源池（线程、连接），防止单一依赖耗尽系统资源。
Timeout
所有跨服务调用必须设置超时，防止慢调用占用资源。

与多智能体系统的映射

  • Coordinator ≈ API Gateway + 编排器：接收请求、分发任务、聚合结果。
  • 专用 Agent ≈ 微服务：各自负责边界清晰的能力（SEO 路径、EEAT 审计、引用评分）。
  • ReAct 循环 ≈ Saga：多步骤推理，失败时可通过轨迹回退或重试。
  • 共享状态 / 事件 ≈ 编舞式：Agent 通过结果缓存与事件触发后续步骤。
  • 风险缓解：当前系统已有步骤预算与重复动作检测；扩展时需加入超时、熔断与隔离。

实践建议

对 SEO 自动化系统：保持 Coordinator 作为编排中枢（可调试），专用 Agent 保持单一职责。关键路径（人工闸门确认）使用强一致协调；中间计算结果可最终一致。扩展多实例时优先引入超时与熔断，避免单 Agent 失败拖垮整个工作流。
