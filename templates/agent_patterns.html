核心模式对比

分类参考 Anthropic《Building effective agents》、LangChain 多智能体文档与 AWS 多智能体架构说明。

模式怎么跑适合场景主要风险与本系统的契合
顺序流水线 / Prompt chaining步骤预定，上步输出作为下步输入，中途可加程序闸门任务可稳定拆解，需要可预测与可调试延迟叠加；路径过硬遇异常会僵最契合 → 已作为 SEO 工作流主骨架（审批台）
Router先分类输入，再交给专家 Agent，最后汇总请求类型清晰：审计、路径、工作流、导图分类错误会走错专家很契合 → 已用规则实现（AI 中心 · 智能路由）
Orchestrator-worker / Supervisor中央 Agent 拆任务、委托工作者并汇总开放式任务，需动态拆分或并行专家监督者迷失会循环或重复派单，需轮次上限契合 Coordinator 层；监督者不要自己做领域工作
分层 / Hierarchical顶层拆解后，子智能体可以再拆层级多、团队分工维护调用链变长，成本与调试难度上升现阶段不需要，一层 Supervisor 足够
并行扇出 / Parallelization独立子任务并行后汇总，或多次投票多领域审计、竞品对比、需提速并发产生更多调用与费用已用于段落 / 引用 / 扇出三项审计并行
Swarm / Handoff控制权按专长交接多轮对话，用户直接与专家交流难并行；上下文逐渐膨胀不适合主工作流，可用于以后的对话咨询
Plan-and-execute先出计划再执行，可按结果重规划目标清楚但步骤可变的研究任务计划质量差会浪费整个执行链可用于竞品调研等开放任务，不用于 17 步管线
ReAct思考 → 行动 → 观察循环，步骤由模型决定工具多、路径难预写的探索循环、重复调用、费用不可预知保留轨迹展示；接 LLM 后才用于开放探索
Debate / Reflection（Evaluator-optimizer）生成与评审循环，或多角色互评评价标准清晰、迭代确能提质多轮调用；标准含糊会空转适合简报打磨（当前：人工「打回重写」最多 2 次）

主要框架对比

以官方文档及 2026 年可核对的对比整理，不是跑分榜。

框架控制模型状态与记忆HITLMCP更适合许可
LangGraph（采用）声明节点、边与共享状态；可嵌入子智能体、Router、Handoff线程检查点 + 跨线程 Store；可配 LangMeminterrupt() + Command(resume)，依赖 checkpointer经 LangChain MCP Adapter需要明确控制流、可恢复流水线与审批点的系统MIT
CrewAI角色化 Crew；顺序或经理层级；Flows 事件驱动任务输出下传；Flows 默认 SQLite 持久化回调式，无图级中断原语有集成快速按角色搭团队MIT
AutoGen / AG2经典 GroupChat + Manager；AG2 v1 改为 workflow / TransitionGraph默认偏内存可人类参与对话，非检查点模型有生态集成会话式研究与多 Agent 讨论见项目许可
OpenAI Agents SDKAgent、Agent-as-tool、Handoff、Guardrail；控制流主要由模型决定Sessions：SQLite、Redis、SQLAlchemy工具 needs_approval，运行态可序列化后恢复Hosted / Streamable HTTP / stdio以 OpenAI 为主的轻量应用MIT
Google ADK协调器 + 子智能体；顺序、循环、并行模板；2.0 起有图工作流Session、state、memory工具确认与图中人工输入（部分实验性）McpToolset已标准化 GCP，或需 Go / JavaApache 2.0

选 LangGraph 的三个理由：① 17 步流水线需要可见的图与可恢复检查点；② HITL 要真正暂停而不是贴一行字；③ Flask 可以直接把 LangGraph 当库引入，不必换主框架。

状态与记忆

短期记忆 = 线程（thread）状态，由 checkpointer 每个超步存快照；长期记忆跨会话，用 Store 按命名空间存储（如 ("prefs", user)、("site", domain)）。生产环境用 Postgres 等持久化实现，InMemorySaver 仅供开发。

本系统：工作流运行态存 data/workflow.sqlite（SqliteSaver），与看板任务 JSON 分开。

MCP vs A2A

MCP 是垂直的：让单个智能体连到工具、API 和资源。A2A 是水平的：让不同团队/组织的智能体互相发现与协作（Agent Card 在 /.well-known/agent-card.json）。

本系统：先用 MCP 接 Search Console、页面抓取等只读工具；只有拆分服务或对接外部 Agent 时才考虑 A2A，不要一开始就微服务化。

人机协同（HITL）

LangGraph 用 interrupt() 暂停图并写入检查点，用 Command(resume=...) 恢复；恢复时节点会从头重跑，闸门前的副作用要保持幂等，并且需要稳定的 thread_id。

本系统：闸门是独立节点，interrupt 之前不做副作用 → 审批台。

评估、可观测与成本

自主智能体意味着更高成本和误差叠加，需要沙箱、防护栏与最大迭代次数。应追踪每个节点、工具调用、token、延迟与错误（LangSmith，或 OpenTelemetry + Langfuse）。

⚠️ 别把 17 个阶段都换成 LLM 调用：评分公式、阶段编排、阈值判断保留为确定性代码。

Anthropic 的三条原则

① 保持简单能用工作流就不用自主智能体；复杂度要用效果换。
② 显式展示规划与轨迹每一步做了什么、为什么，都要能看见（本系统的执行轨迹）。
③ 打磨工具接口把工具当一等公民设计（本系统的可替换 StageTool 接口）。
