核心安全协议

HITL / I-HITL（人工介入） 关键操作需显式人工批准。I-HITL 要求即使本地环境被攻破，仍需可信设备确认。本系统：发布闸门强制人工确认。
Kill Switch（紧急关闭） 三要素：① 全局停止新任务 ② 撤销已发凭证 ③ 清理孤儿进程。本系统：步骤预算耗尽 + 重复动作检测 = 基础 Kill Switch。
委派权限收窄 每跳委派权限取交集（自身角色 ∩ 原始授权）。子 Agent 不得继承编排器全部权限。本系统：专用 Agent 单一职责。
审计与可追溯 完整记录操作轨迹、决策依据、异常检测。本系统：ReAct 轨迹日志已具备基础可追溯。

Kill Switch 三要素

全局停止停止新步骤、新运行、队列工作。由编排器/网关执行。
凭证撤销使已签发令牌失效。防止停止后仍能访问。
孤儿清理扫描并终止已启动但未结束的进程与任务。
本系统现状步骤预算与重复检测已实现软停止；硬停止需外部控制面。

委派安全规则

  • 身份认证：Agent 间通信需相互认证（mTLS / 工作负载身份），不信任“内部”请求。
  • 权限收窄：每跳委派权限取交集，子任务仅获所需最小权限。
  • 结构化交接：Agent 间传递使用受约束模式，避免自由文本注入。
  • 零信任链：Agent-ZTA 风格，运行时安全状态双向传播，异常分支可隔离。
