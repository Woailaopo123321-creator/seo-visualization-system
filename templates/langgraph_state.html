状态模型

类型化状态使用 TypedDict、Pydantic 或 dataclass 定义。节点读取完整状态，返回部分更新（Partial State）。
共享账本状态不是可直接修改的内存，而是通过 reducer 记账的共享对象。节点提交增量，reducer 合并。
通道（Channel）每个状态键是一个通道。可配置独立 reducer 与默认值。

Reducer 机制

合并规则节点不直接修改状态，只提交更新。Reducer 函数决定如何合并旧值与新更新（如列表追加、覆盖、自定义聚合）。
并行安全同一 super-step 中多个节点的更新通过 reducer 确定性合并，避免冲突。
示例消息列表常用 append reducer；计数器可用累加；自定义字段可覆盖或保留最新。

检查点与线程

检查点每个 super-step 结束后保存完整状态快照。包含 channel_values、版本、元数据与父检查点引用。
线程thread_id 标识一次独立运行。多租户场景下每个对话或任务使用独立线程。
待写缓冲节点失败时，已完成节点的写入暂存为 pending writes，恢复时跳过已成功节点。
持久化模式async（默认后台写）、sync（逐步写）、exit（仅结束时写）。生产推荐数据库后端。

短期 vs 长期记忆

Checkpointer线程内短期记忆。支持恢复、HITL 中断、时间旅行。范围：单次运行。
Store跨线程长期记忆。存储用户偏好、事实、共享知识。节点可直接读写。
组合使用Checkpointer 跟踪当前线程进度；Store 维护跨会话知识。

与本系统关系

  • 当前系统使用进程内 TTL 缓存（30s）与 ReAct 轨迹日志。
  • 若需跨请求恢复与 HITL 暂停，可评估引入检查点机制。
  • Reducer 思想可借鉴：节点返回增量，由协调层确定性合并。

LangGraph 状态管理的核心是类型化共享状态 + reducer 合并 + 检查点持久化。节点只提交增量，系统保证确定性合并与可恢复执行。
