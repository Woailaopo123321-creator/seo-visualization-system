当前系统状态

Coordinator 使用进程内 TTL 缓存（30秒），基于任务哈希精确匹配。适合单进程模拟，但无法跨实例共享，也不处理语义相似请求。

四层分布式缓存模型

1. 应用内内存缓存（当前实现）

极低延迟、零网络开销。适合热路径重复调用。TTL 失效，无主动失效。

2. 共享键值层（Redis / Valkey）

跨进程、跨实例共享。支持 Pub/Sub 失效广播、分布式锁防缓存击穿。适合 Agent 中间结果与工具输出。

3. 语义 / 向量缓存

对相似查询（而非精确匹配）返回缓存结果。使用嵌入相似度阈值（通常 0.85–0.95）。显著提升 ReAct 循环中重复意图的命中率。

4. Agent 感知 KV / 前缀缓存

针对 LLM 调用的 KV Cache 管理。分支计数（live branch counting）优先保留仍被活跃 Agent 分支引用的块，优于纯 LRU。研究显示可降低 P95 TTFT 最高 14x。

失效策略对比

TTL 失效简单可靠，无协调开销当前使用
事件驱动失效写操作后 Pub/Sub 广播失效推荐
版本戳 / 快照键策略或数据变更时自动 miss强一致性
依赖图失效工具写操作触发相关读缓存失效复杂度高
工作负载感知淘汰综合重计算成本、依赖数、调用频率研究验证

针对本系统的优化建议

  • 短期：为 citation_score、passage_audit 等高频工具结果增加更长 TTL，并区分可缓存与不可缓存工具。
  • 中期：引入 Redis 共享层，支持多实例部署与跨请求共享。
  • 长期：对 SEO 学习路径与引用评分加入语义缓存；对 ReAct 轨迹应用分支感知保留策略。
  • 失效：人工闸门确认后主动清除相关缓存；数据更新时使用版本戳。

研究要点

Workload-Aware Caching 研究显示，结合重计算成本与依赖计数的淘汰策略可比标准 LRU 降低延迟最高 64.7%。

Agent-aware KV 管理（分支计数）在真实轨迹上可实现最高 14x 的 P95 TTFT 改善。
